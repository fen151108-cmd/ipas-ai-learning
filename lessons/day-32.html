多模態輸入與輸出

模態看資料形式，任務看轉換方向；多模態能連接文字、圖像、語音與影片，但每一路輸入輸出都要分開驗收。

今天不背工具名稱，而是用「輸入模態 → 理解／融合 → 輸出模態 → 驗收」讀懂跨模態任務，避開把檔案格式、介面功能與真正的多模態能力混在一起。

KNOWLEDGE MAP

一、先定位：從單一生成任務走向跨模態工作流

任務與工具配對›提示與輸入›多模態理解／融合›多模態輸出›逐模態驗收

iPAS 科目二把「生成式 AI 應用領域與常見工具」及「如何善用生成式 AI 工具」列入評鑑內容；官方學習指引進一步把多模態處理列為生成式 AI 的重要能力與發展方向。[1][2]

上位／前置生成式 AI、工具任務配對、提示與查證
本課核心模態、轉換方向、融合、輸出與驗收
相鄰／後續企業需求、資料與資安、POC、部署監控
考題讀法先圈出輸入是文字、圖像、語音或影片，再圈出輸出；箭頭方向通常比工具名稱更能決定任務分類。
MODALITY IS A DATA FORM

二、正確定義：模態是資訊呈現形式，不是副檔名

TEXT文字

句子、文件、字幕、表格文字與程式碼等符號序列。

例：物品名稱與描述。
IMAGE圖像

照片、掃描頁、插圖、圖表與畫面截圖等視覺資料。

例：遺失物照片。
AUDIO語音／音訊

口語、環境聲、音效與音樂等隨時間變化的聲音訊號。

例：使用者語音補充。
VIDEO影片

連續影格加上時間資訊，通常還可能包含音軌與字幕。

例：物品出現位置片段。

單模態任務只處理一種模態；多模態系統能接收、對齊、結合或產生兩種以上模態。官方指引以文字、圖像、音訊等模態的結合，以及文字、圖像、語音、影片的協同生成，說明多模態發展方向。[2]

JPEG → PNG仍是圖像模態；只是格式轉換≠圖像 → 文字模態改變；是跨模態任務
INPUT → OUTPUT

三、先看箭頭：同一批模態，方向不同就是不同任務

文字→文字摘要、改寫、問答同模態轉換
文字→圖像依描述生成畫面跨模態生成
圖像→文字圖像描述、OCR、視覺問答理解／辨識後輸出文字
語音→文字語音辨識、逐字稿STT／ASR
文字→語音語音合成、朗讀TTS
影片→文字片段摘要、事件描述需處理時間脈絡

官方指引舉出文字轉圖像、語音與文字轉換，以及 AI 影音剪輯與影片生成等多模態整合例子。[2] 判斷時不能只看到「語音」就選語音生成，也不能只看到「圖片」就選圖像分類；要完整讀取輸入與輸出。

ALIGN → FUSE → RESPOND

四、多模態不只「收很多檔案」：重點是對齊與融合

01 · ENCODE各自表徵

把文字、圖像或語音轉成模型可處理的表示。

→
02 · ALIGN跨模態對齊

判斷哪些詞、聲音片段或畫面區域彼此相關。

→
03 · FUSE融合訊息

把互補線索結合，處理衝突、缺漏與時間順序。

→
04 · GENERATE依任務輸出

產生文字、圖像、語音、影片或結構化資料。

系統表面實際能力是否足以稱多模態判斷理由
網頁可附圖片圖片只被儲存，模型完全不讀取不足介面支援上傳，不等於模型理解圖像
語音先轉逐字稿，再交給文字模型語音辨識＋文字處理的管線多模態工作流跨模態，但可能由多個單模態元件串接
照片＋問題一起判讀對齊視覺區域與文字問題後回答是模型同時利用兩種模態完成任務
同時輸出 PDF 與 TXT內容仍只有文字不一定多檔案格式不等於多種資訊模態
ONE SCENARIO THROUGHOUT

五、貫穿情境：遺失物登記不是「丟照片給模型」就結束

公共空間團隊要建立中性的遺失物登記流程。使用者可上傳物品照片，再用語音補充「在閱覽區靠窗座位附近找到」；系統要產生可搜尋的文字紀錄與語音確認。這是原創教學情境，不對應任何真實組織。

INPUT A · IMAGE物品照片

可見顏色、形狀與圖案；不保證畫面外資訊。

INPUT B · SPEECH語音補充

提供發現位置與時間線索；先辨識成文字。

→
FUSION對齊與去衝突

確認語音描述是否對應照片；衝突時標待確認。

→
OUTPUT A · TEXT結構化紀錄

物品類型、可見特徵、地點與證據來源。

OUTPUT B · SPEECH語音確認

朗讀紀錄，讓使用者確認後才送出。

照片支持「深色水壺，瓶身有白色圖案」
語音支持「在閱覽區靠窗座位附近找到」
兩者都不支持「物品屬於某位固定使用者」

模型若由照片直接猜測所有者、材質或品牌，就是把可見線索延伸成未經支持的主張。多模態線索增加，不代表所有不確定性都消失。

VALIDATE EACH LANE

六、驗收不是一次打勾：每個模態有不同失敗型態

文字語意與事實

核對名稱、數字、時間、來源、遺漏與幻覺。

圖像內容與畫質

檢查構圖、細節、文字失真、偏見、解析度與權利。

語音辨識與聽感

核對專有詞、數字、斷句、語速、雜音與可理解性。

影片跨時間一致

檢查前後畫面、動作連續、音畫同步、字幕與片長。

端到端再檢查輸入品質 → 模態對齊 → 融合判斷 → 輸出品質 → 人工確認 → 保存與發布

官方指引在圖像生成情境提醒解析度、版權合法性與推論時間都需考量，也把隱私、安全、版權管理與內容過濾列為工具使用的重要面向。[2] 因此「能生成」只是能力存在，「能採用」還需要依用途驗收。

EXAM TRAPS

七、容易混淆處與 iPAS 題目判斷訊號

模態 vs. 格式JPEG、PNG 都是圖像

格式改變不一定跨模態；圖像轉文字才改變資訊形式。

輸入 vs. 輸出語音 → 圖像 ≠ 圖像 → 語音

相同兩種模態，只要箭頭反向，任務就不同。

多模態 vs. 多功能功能多 ≠ 模態多

同時做摘要、翻譯、分類，若都只處理文字，仍可能是單模態。

多模態 vs. 多檔案檔案多 ≠ 模態多

十份 PDF 若只抽取文字，核心處理仍可能只有文字。

理解 vs. 生成看圖回答不等於生成圖像

前者主要理解視覺並輸出文字；後者產生新的視覺內容。

更多線索 vs. 一定正確多模態 ≠ 零幻覺

輸入仍可能模糊、衝突或被錯誤對齊，必須保留證據邊界。

  1. 「接收語音，依內容產生圖片」：輸入語音、輸出圖像，判為語音生成圖片。
  2. 「理解文字訊息，調用相關圖片與影片回覆」：同時跨文字與視覺媒體，優先想到多模態模型或多模態工作流。
  3. 「會上傳圖片」：還要確認模型是否真的讀取視覺內容；上傳元件本身不是證據。
  4. 「逐字稿」：通常是語音轉文字；「朗讀」通常是文字轉語音。
  5. 「影片」：除了影像內容，還要注意時間順序、音軌、字幕與同步。
  6. 「品質」：先分模態設指標，再做端到端驗收，不要只看一個總分。
EXAM METHOD

八、五步判斷法：入、向、融、出、驗

入輸入：題目提供哪些模態？是原始語音、圖片，還是已轉好的文字？
向方向：從哪一種模態轉到哪一種？先把箭頭寫出來。
融融合：是否真的對齊並共同使用多種模態，還是只有介面可上傳？
出輸出：產生新內容、辨識既有內容，還是調用既有媒體？
驗驗收：各模態與端到端流程要檢查什麼品質、權利與風險？
