Transformer 與自注意力

位置告訴模型「先後」，自注意力決定「此刻該看哪裡」，多頭則同時看不同關係。

今天不背架構名詞，而是把 Token 如何得到上下文表示拆成一條路：嵌入＋位置 → Query、Key、Value → 注意力權重 → 加權取值 → 多頭整合 → 遮罩控制。

KNOWLEDGE MAP

一、先定位：上一課會「逐步生成」，這一課回答「如何讀懂上下文」

Token 序列›Transformer›自注意力›上下文表示›下一步預測

iPAS 科目二把 Transformer 架構與自注意力列入生成式 AI 的技術脈絡，並指出自注意力有助於處理長距離依賴與學習序列結構。[1][3] 原始 Transformer 論文則以注意力機制作為核心，並以堆疊的自注意力與逐位置前饋網路組成編碼器與解碼器。[4]

上位／前置神經網路、向量表示、Token、逐步機率生成
本課核心Transformer、自注意力、位置、Q／K／V、多頭與遮罩
相鄰／後續提示設計、上下文視窗、幻覺、RAG 與工具整合
先分清層級Transformer 是整體架構；自注意力是架構裡的重要機制；注意力權重是一次計算的結果；多頭注意力是多組投影平行計算後再整合。
ARCHITECTURE ≠ ONE MECHANISM

二、Transformer 不是「只有注意力」的一個方塊

原始架構會重複堆疊注意力子層與逐位置前饋網路，並使用殘差連接與層正規化；因此「Transformer＝自注意力」是過度簡化。[4]

INPUTToken 嵌入＋位置資訊內容與順序一起進入
↓
CONTEXT多頭自注意力各位置依關聯取用資訊
↓
TRANSFORM逐位置前饋網路對每個位置做非線性轉換
↓
OUTPUT上下文化表示供下一層或輸出頭使用
殘差連接把子層輸入繞接到輸出，協助深層訊息與梯度傳遞。
層正規化調整層內表示尺度，配合堆疊訓練。
重複堆疊每一層可在前一層表示上再整合更高階關係。
CONTENT NEEDS ORDER

三、為什麼還要位置資訊？同一批字，順序不同，意思可能不同

原始 Transformer 不使用循環或卷積，因此必須把 Token 的相對或絕對位置資訊注入輸入表示；論文將位置編碼加到嵌入上，讓模型可利用序列順序。[4]

內容相同系統 提醒 使用者誰做動作？誰接收提醒？
⇄
順序改變使用者 提醒 系統詞相同，但角色關係不同。
輸入表示 = Token embedding + position informationToken 嵌入回答「這是什麼內容」；位置資訊補上「它在序列哪裡」。兩者用途不同。
QUERY · KEY · VALUE

四、Q、K、V：先比對關聯，再取回內容

在自注意力中，Query、Key 與 Value 都來自同一段序列的表示；注意力會用 Query 與各 Key 的相容程度形成權重，再對對應的 Value 做加權和。[4]

Q · QUERY我現在要找什麼？

目前位置提出的查詢方向。

K · KEY我和查詢有多相關？

每個候選位置用來比對的索引特徵。

V · VALUE若相關，要取回什麼？

依權重被加總的實際內容表示。

Attention(Q, K, V) = softmax(QKᵀ / √dk)V
  1. 比對：Q 與 K 做點積，得到關聯分數。
  2. 縮放：除以 √dk，避免維度大時分數過度放大。
  3. 正規化：Softmax 把分數轉成可比較的權重。
  4. 取值：用權重加總 V，形成新的上下文表示。
最常見顛倒Key 不是最後輸出的內容，Value 才是被加權取用的內容；Q 與 K 先決定「看多少」，權重再作用在 V。
ONE SCENARIO THROUGHOUT

五、貫穿情境：把家庭採買清單整理成期限提醒

輸入：「請把週六採買清單中的燕麥與洗碗精整理成提醒，並標示週六前完成。」以下權重只用來教學示意，不代表真實模型，也不宣稱是模型的完整解釋。

INPUT SEQUENCE請把週六採買清單中的燕麥與洗碗精整理成提醒，並標示週六前完成。
目前位置的 Query完成這個位置要整合哪些前文？
週六前高關聯：期限0.34
採買清單高關聯：任務0.26
燕麥中關聯：項目0.18
洗碗精中關聯：項目0.16
請把低關聯：語氣0.06
整合後的教學示意「完成」的位置帶入期限、任務與項目資訊，形成具上下文的表示。注意力不是把某個詞整句複製過來，而是依權重混合 Value 表示。
MULTIPLE RELATIONSHIP LENSES

六、多頭注意力：不是重複看同一件事，而是允許不同表示子空間並行

多頭注意力會對 Q、K、V 做多組不同的線性投影，平行計算各頭後串接再投影；原始論文指出，這讓模型能同時關注不同位置與不同表示子空間的資訊。[4]

HEAD A期限關係「完成」較關注「週六前」
HEAD B項目並列連結「燕麥」與「洗碗精」
HEAD C任務角色連結「整理」與「採買清單」
CONCAT + PROJECT整合各頭輸出得到一個新的位置表示
不要過度解讀頭可以學到不同關係，但不能因某次權重較高，就直接斷言那是模型的唯一理由、因果證據或完整可解釋性。
WHO MAY LOOK WHERE?

七、一般自注意力與遮罩自注意力：差在能不能看未來

原始 Transformer 的解碼器會遮住後續位置，使第 i 個位置的預測只能依賴較早、已知的輸出，藉此保留自迴歸生成條件。[4]

類型可看範圍主要用途題目訊號
一般自注意力同一輸入序列中允許的各位置形成整段輸入的上下文表示「全句互相參照」「同序列內關聯」
遮罩自注意力目前位置以前的已知內容避免生成時偷看到未來答案「自迴歸」「只依賴先前 Token」「因果遮罩」
交叉注意力Query 來自解碼器；K、V 來自編碼器輸出讓輸出位置參照來源序列「輸入與輸出兩段序列」「編碼器—解碼器」
位置 4 可看：12345 ×6 ×未來位置被遮住
DON’T COLLAPSE THE CONCEPTS

八、五組容易混淆的差異

Transformer vs. 自注意力整體架構 ≠ 單一機制

Transformer 還包含前饋網路、殘差、正規化與位置資訊等元件。

位置資訊 vs. 注意力序列順序 ≠ 關聯權重

位置補順序；注意力依目前表示計算位置間的取用比例。

Key vs. Value用來比對 ≠ 被加權取回

Q 與 K 形成權重，權重再加總 V。[4]

多頭 vs. 多層同層平行 ≠ 深度堆疊

多頭在同一注意力子層平行；多層是前一層輸出再送往下一層。

注意力高 vs. 因果重要運算權重 ≠ 完整解釋

權重描述該次計算的混合比例，不能單獨證明人類語意或因果。

平行訓練 vs. 一次生成全文訓練計算 ≠ 推論解碼

Transformer 可平行處理訓練位置，但自迴歸推論仍逐步產生下一個 Token。[4]

EXAM TRAPS

九、iPAS 題目判斷訊號

  1. 「同一序列各位置彼此建立關聯」：指向自注意力。[3][4]
  2. 「沒有循環仍要知道先後」：指向位置編碼或位置資訊。[4]
  3. 「Q 與 K 算相似度，再加權 V」：先比對、後取值，不要顛倒。[4]
  4. 「同時從不同表示子空間看關係」：指向多頭注意力。[4]
  5. 「生成時不能看後面的正確 Token」：指向遮罩自注意力。
  6. 「注意力權重最高就是模型唯一理由」：錯；權重不是完整因果解釋。
  7. 「Transformer 完全等於自注意力」：錯；自注意力是核心子層之一。
  8. 「可平行訓練，所以推論一次產生全文」：錯；自迴歸解碼仍是逐步生成。

十、六問還原法：看到 Transformer 題先問這六件事

01層級：題目在問架構、子層，還是權重結果？
02位置：模型如何知道 Token 的先後？
03來源：Q、K、V 是否來自同一序列？
04運算：QK 比對後，權重作用在哪個 V？
05視角：是多頭平行，還是多層堆疊？
06可見性：目前位置能否看到未來 Token？
